# Traceback Lab

Локальная лаборатория для расследования багов в Python. Загрузите исходники, опишите сбой и откройте функции-кандидаты прямо на строках нужной версии. На трёх исторических задачах Requests можно раскрыть патч разработчика и увидеть, куда в выдаче попало исправление.

## Запуск

Распакуйте архив, откройте терминал в каталоге с `run.py` и выполните команду. Рекомендуется Python 3.12, поддерживаются версии 3.11–3.13.

~~~sh
python run.py
~~~

Откройте **http://127.0.0.1:8000**. Первый запуск создаст окружение и установит зависимости. Интерфейс, веса Compact-64, индексы и примеры входят в архив. Для работы с ними достаточно CPU. Ключи API не нужны.

Для запуска с предобученным UniXcoder используйте `python run.py --neural`. При первой настройке загрузятся PyTorch, Transformers и около 0,5 ГБ весов. Модель, используемую текущим сервисом, можно посмотреть в разделе «Лаборатория».

## Первое расследование

- **На своём коде.** Нажмите «Подключить код». Выберите `.py`, ZIP с проектом или вставьте исходник. Вкладка «Проверки кода» сразу показывает найденные проблемы и строки. Для встроенного примера выберите «Вставить код» → «Вставить учебный пример». В функции `enqueue_packet` очередь из значения по умолчанию разделяется между вызовами.
- **По описанию сбоя.** Перейдите в «По симптому» и введите, например, *Packets accumulate across separate calls to enqueue_packet*. При наличии добавьте traceback. Нажмите «Найти функции». Вкладка «Почему здесь» показывает совпавшие идентификаторы, ранги поиска и найденные связи.
- **На реальном исправлении.** Выберите кейс «POST после перенаправления». После поиска откройте «Раскрыть исправление», затем «Сравнить с BM25». Сравнение использует исходный текст завершённого запроса и тот же снимок. Изменение черновика не меняет сохранённый прогноз.
- **Вернуться к работе.** Раздел «История» открывает сохранённую выдачу. Кнопка со стрелкой вниз у кандидатов скачивает Markdown-отчёт. Ссылка в адресной строке открывает расследование на том же локальном сервисе.
- **Настроить интерфейс.** Вверху справа откройте «Оформление». Доступны «Графит», «Бумага» и системная тема, с кобальтовым, фиолетовым или янтарным акцентом. Выбор запоминается в браузере.

Язык интерфейса — русский. Поиск по описанию оценивался на английских баг-репортах. Найденная функция — место для проверки разработчиком. Историческая метка означает, что функцию менял патч.

## Что можно найти без описания

После импорта доступны пять статических проверок. Они показывают синтаксические ошибки, изменяемые значения аргументов по умолчанию, повторяющиеся константные ключи словаря, заведомо непустой кортеж в условии и пустой обработчик `except: pass`. Синтаксис разбирает установленная версия Python. Каждая находка содержит правило, объяснение, путь и строку. Пустой список означает, что эти пять правил не сработали.

Веб-импорт создаёт снимок в `.state/projects/snapshots/`. Сервис читает файлы как данные. Загруженный код и история расследований остаются в каталоге состояния, исключённом из Git. Лимиты веб-импорта составляют 1 МиБ на .py, 16 МиБ на ZIP, до 1000 подходящих Python-файлов и 32 МиБ исходников после распаковки. Для больших репозиториев доступен CLI ниже. 

## Какой поиск выбрать

Замер на 25 размеченных исторических задачах из Requests, Flask, pytest и seaborn. Из исходных 30 исключили три демонстрации и две задачи без доступной функции до исправления. Ни одна из четырёх библиотек не входила в корпус обучения Compact-64. Индексы перед измерением были прогреты.

| Метод | Попадание в топ-1 | Попадание в топ-5 | Recall@50 |
| --- | ---: | ---: | ---: |
| BM25 | 6/25 | 13/25 | 78% |
| BM25 со стеком и графом | 6/25 | 13/25 | 78% |
| Compact-64 | 2/25 | 3/25 | 42% |
| BM25 + Compact-64, стек и граф | 4/25 | 12/25 | 70% |

При обычном запуске интерфейс выбирает BM25 со стеком и графом. В настройках поиска можно включить компактную модель отдельно или в гибридном режиме. Топ-5 базового и гибридного методов отличается на один случай. Размер этой выборки допускает вывод о конкретных 25 задачах. В JSON сохранены отдельные прогнозы, условия эксперимента и интервалы bootstrap. [Отчёт по 25 задачам](reports/compact_evaluation.json) · [Отдельный отчёт по трём демо с UniXcoder](reports/demo_evaluation.json)

### Откуда взялись веса

Compact-64 — двухбашенная модель с общей таблицей токенов и отдельными нелинейными проекциями описания и кода. Её обучили в PyTorch на 4 984 парах «docstring → реализация» из стандартной библиотеки CPython. На этапе обучения текст docstring исключался из тела целевой функции. На валидации по отдельным модулям было 525 пар. Лучший обученный checkpoint дал MRR 0,294 на этой вспомогательной задаче, начальные веса — 0,281. В релизе лежат FP16-веса, при поиске используется NumPy на CPU. [Параметры и журнал обучения](src/traceback_lab/assets/compact/training.json)

Для повторения обучения установите ML-зависимости. Для идентичной подборки используйте CPython 3.12.14 с таким же составом стандартной библиотеки. Хэш подготовленных пар сохраняется в журнале.

~~~sh
uv run --extra ml python -m traceback_lab.ml.train_compact --output models/compact-retrained
python run.py --encoder models/compact-retrained
~~~

Собственные эксперименты с историческими парами «баг-репорт → функция», трудными негативами и CodeBERT описаны ниже.

**Состояние реализации**

| Компонент | Состояние |
|---|---|
| Tree-sitter, снимки, SQLite FTS5 | Реализованы и проверены |
| Traceback, RRF, граф, бюджеты кандидатов | Реализованы и проверены |
| Compact-64 | Обученные веса включены, NumPy inference на CPU |
| UniXcoder | Реальный inference на CPU, загрузка весов первой настройкой |
| Обучение bi-encoder и hard-negative mining | Реализованы, сквозная проверка обучения и перезагрузки на маленькой тестовой сети |
| Обучение cross-encoder | Реализовано, сквозная проверка на маленькой тестовой сети |
| Калибровка | Отдельный этап на независимых данных с проверкой совместимости |
| React, FastAPI, раскрытие патча | Собранный локальный интерфейс и API |
| Большой исследовательский прогон | Требует собственного подготовленного корпуса и обучения |

Ранжировщик подключается после обучения. CrossEncoder проверяет метаданные checkpoint перед использованием. Расширенный режим использует исходные предобученные веса UniXcoder. Три демонстрационных кейса закреплены отдельно от обучающего разбиения.

**Архитектура**

| Этап | Поведение |
|---|---|
| Индексирование | Читает заданный git-коммит, выделяет функции и вызовы, сохраняет оригинальный код |
| BM25 | Ищет имена, диагностику и текст, разделяя составные идентификаторы |
| Bi-encoder | Кодирует запрос и обзор функции независимо, сравнивает нормированные векторы |
| RRF | Объединяет исходные списки по 60 функций от каждого метода |
| Кандидаты | До 10 кадров стека, 30 прямых кандидатов, 10 соседей, заполнение свободных мест |
| Cross-encoder | Читает запрос и до трёх окон функции, агрегирует оценки через log-mean-exp |
| Калибровка | Оценивает событие попадания первого места в функции исторического исправления |
| Раскрытие | Отдельно загружает патч и сопоставляет его с зафиксированной выдачей |

Индекс публикуется атомарно. Запрос закрепляется за одним снимком. Модели сохраняются неизменяемыми версиями с атомарным указателем current.json. Патчи, метки и исходные записи корпуса лежат отдельно от поискового индекса.

**Свой репозиторий**

Для индексации определённого Git-коммита или большого каталога используйте CLI из созданного окружения. В Windows команда начинается с .venv\Scripts\python.exe, в Linux и macOS — с .venv/bin/python.

~~~sh
.venv/bin/python -m traceback_lab index /path/to/repository --revision COMMIT_SHA --name owner/repo
~~~

Обновите страницу и выберите новый снимок. Git нужен для чтения коммита. Для каталога с исходниками можно опустить --revision, тогда индексируется рабочее дерево. Индексатор читает исходники как данные.

~~~sh
.venv/bin/python -m traceback_lab index /path/to/repository --revision COMMIT_SHA --encoder models/unixcoder
~~~

**Среда для экспериментов**

Для воспроизводимой CPU-среды используется uv.lock.

~~~sh
python -m pip install uv
uv sync --locked --extra ml --extra data --extra test
uv run python -m traceback_lab setup-models --include-codebert
uv run python -m pytest -q
~~~

CLI принимает --device cuda при установленной CUDA-сборке PyTorch. В lock-файле зафиксирован CPU-источник PyTorch. Время полного обучения и требования к памяти зависят от длины функций и числа негативов.

**Подготовка корпуса**

Импортер сохраняет исходную запись и её хэш, снимок кода, патч, проверку применимости и качество сопоставления функций. Следующая команда повторяет подборку для инженерной проверки импортера. Она подготавливает 30 кейсов из четырёх репозиториев и может скачать значительный объём git-истории.

~~~sh
uv run python -m traceback_lab --data study import-swe --dataset SWE-bench/SWE-bench_Lite --split test --offset 0 --limit 300 --repos psf/requests,pallets/flask,pytest-dev/pytest,mwaskom/seaborn --role unassigned
uv run python -m traceback_lab --data study audit
~~~

Это собственный протокол локализации на исторических задачах. Официальный split источника сохраняется в метаданных. Размер и состав выбранной части фиксируются перед сравнением моделей.

Команда ниже воспроизводит сравнение из таблицы по списку задач инженерного аудита. Для сравнения задержек запустите её повторно после создания векторов.

~~~sh
uv run python -m traceback_lab --data study evaluate --compact --splits unassigned --exclude-cases data/cases --modes bm25,context,dense,hybrid --no-rerank --output reports/reproduced_compact.json
~~~

Для большого train укажите подходящую --revision SWE-bench и проверьте её схему и доступность. В приложенном ТЗ указан кандидат ревизии архива. Статус загрузки конкретного архива определяется при выполнении импорта.

Есть сборщик собственных публичных issue–PR пар.

~~~sh
uv run python -m traceback_lab collect-github psf/requests --pulls 1963,2674 --output source_rows.json
uv run python -m traceback_lab --data study import-json source_rows.json --role unassigned
~~~

Сборщик ищет явную ссылку на issue в описании PR и сохраняет время наблюдения текста. Применимость diff к выбранной базе проверяет следующий этап. Текущий текст issue получает статус историчности unverified.

**Разбиение**

Задайте временные границы и удержанный репозиторий до сравнения качества.

~~~sh
uv run python -m traceback_lab --data study split --train-before 2019-01-01 --validation-before 2020-01-01 --calibration-before 2021-01-01 --holdout-repo mwaskom/seaborn
~~~

Это пример границ. Их выбирают по распределению своего корпуса. Единый split_manifest.json публикуется атомарно. Обучение читает train, выбор checkpoint использует validation. Калибровочный интервал разделяется по группам и времени на calibration_fit и calibration_threshold. Поздние кейсы получают test, удержанный репозиторий — holdout. Демонстрационные кейсы остаются в demo.

Одинаковые изменения с разными координатами и повторный текст запроса объединяются в группы. Аудит дубликатов и историчности текста дополняет автоматическую обработку.

**Главный эксперимент**

~~~sh
uv run python -m traceback_lab --data study train-bi --base models/unixcoder --output models/random_stage1 --epochs 2 --seed 31
uv run python -m traceback_lab --data study mine --encoder models/random_stage1 --output study/negatives.json
uv run python -m traceback_lab --data study train-bi --base models/random_stage1 --negatives study/negatives.json --output models/hard_stage2 --epochs 2 --seed 31
uv run python -m traceback_lab --data study train-bi --base models/random_stage1 --output models/random_stage2 --epochs 2 --seed 31
~~~

Контрольный второй этап получает столько же эпох и шагов, сколько этап с трудными негативами. В метаданных checkpoint сохраняются конфигурация, обновления, исходные case_id и манифест корпуса.

Начальные параметры выбраны для управляемого расхода памяти — micro-batch 1, накопление 4, до 12 негативов. Они меняются аргументами. Реальный пул in-batch негативов определяется micro-batch.

~~~sh
uv run python -m traceback_lab --data study train-cross --base models/codebert --encoder models/hard_stage2 --negatives study/negatives.json --output models/reranker --epochs 2
~~~

Кандидаты обучения ранжировщика берутся из mining и дополняются случайными функциями. Известные положительные функции исключаются из отрицательных. В валидации используются фактические кандидаты поиска.

**Оценка**

~~~sh
uv run python -m traceback_lab --data study evaluate --splits test,holdout --modes bm25,dense,hybrid --encoder models/hard_stage2 --no-rerank --output reports/retrieval.json
uv run python -m traceback_lab --data study evaluate --splits test,holdout --modes bm25,dense,hybrid --encoder models/hard_stage2 --reranker models/reranker --output reports/reranked.json
uv run python -m traceback_lab compare reports/retrieval.json reports/reranked.json --mode hybrid
~~~

Есть --no-graph, --no-rerank, --budget 20/50/100 и быстрый профиль. Отчёты включают case_id, модели, кандидатов, Hit@K, Recall@K, MRR, условное качество ранжирования, среднее по репозиториям и задержки. Парное сравнение использует bootstrap по группам исправлений.

~~~sh
uv run python -m traceback_lab evaluate --splits demo --modes bm25,dense,hybrid --encoder models/unixcoder --output reports/demo_evaluation.json
~~~

На включённых трёх кейсах гибридный поиск дал Hit@5 3/3, BM25 — 2/3 и готовый UniXcoder — 2/3. Это результат на демонстрационной подборке. В отчёте видны отдельные промахи первого места. Перенос на независимые задачи проверяется отдельным test и holdout прогоном.

**Калибровка**

~~~sh
uv run python -m traceback_lab --data study calibration-records --split calibration_fit --encoder models/hard_stage2 --reranker models/reranker --output study/calibration_fit.json
uv run python -m traceback_lab --data study calibration-records --split calibration_threshold --encoder models/hard_stage2 --reranker models/reranker --output study/calibration_threshold.json
uv run python -m traceback_lab calibrate --fit study/calibration_fit.json --threshold study/calibration_threshold.json --output models/calibration.json
python run.py --encoder models/hard_stage2 --reranker models/reranker --calibrator models/calibration.json
~~~

Проверяется отсутствие пересечения case_id и групп. Калибратор привязывается к точной версии системы. При несовместимости возвращается статус incompatible. До подключения калибратора интерфейс показывает ранги и наблюдаемые свидетельства.

**Ограничения и следующие измерения**

Граф использует статически разрешаемые вызовы. Приблизительные методы сохраняются, начальное расширение использует однозначные связи. CodeBERT и калибратор требуют собственного обучения. Полный эксперимент на тысячах исторических задач ещё предстоит выполнить.

У включённых issue историчность текста имеет статус unverified. Подтверждено применение патча к базе и механическое сопоставление функций. Динамическое воспроизведение старых багов тестами отмечено как not_run.

Проверено в Linux с Python 3.12 и CPU. Windows и macOS поддерживаются структурой launcher, отдельного запуска на этих системах в данном прогоне не было.

Подробная архитектура находится в docs/Architecture.md. Условия моделей и данных приведены в docs/MODEL_CARD.md и docs/DATA_CARD.md.
